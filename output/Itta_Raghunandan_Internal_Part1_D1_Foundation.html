2. Engine Finding — Yogakāraka Over-Detection Bug

Location: app/derived/factors.py::is_yoga_karaka()

Root cause: KENDRA = {1,4,7,10} and TRIKONA = {1,5,9} both include house 1. The function checks any(h in KENDRA for h in owned) and any(h in TRIKONA for h in owned) — a planet that owns ONLY house 1 (plus any other non-kendra/trikona house) satisfies both conditions via house 1 alone, without genuinely owning a distinct kendra AND a distinct trikoṇa.

Observed effect on this chart: Raw output was yoga_karakas: ['Venus', 'Saturn']. Saturn owns H1+H2 only — H1 alone satisfies both set memberships. Saturn is NOT a true yogakāraka by classical definition (BPHS requires kendra AND trikoṇa lordship over two distinct houses beyond the automatic Lagna-lord benefic status).

Cross-check: Same bug reproduces on ajay_kumar fixture (Mars flagged yogakāraka for Scorpio Lagna via H1+H6 ownership) — Ajay's original hand-written Validation.md correctly avoided this by treating Mars as "Lagna Lord (Special)" separately from the true yogakāraka Jupiter. The bug exists in code but was masked by manual correction in that older doc.

Action taken this reading: Manually overrode to Venus-only per classical rule. Recommended fix (out of scope for this reading): require owned houses to intersect KENDRA∖{1} and TRIKONA∖{1} as two separate non-empty sets, OR check kendra/trikona membership excluding house 1, treating H1 lordship as a separate "svāmī" flag.
