# Jyotisha — File Inventory & AST Reference

> Technical documentation reference. Generated by walking every in-scope Python module
> with `ast.parse` (source parsed as text — never imported, so Swiss-Ephemeris/runtime
> side effects and heavy dependencies cannot interfere) and extracting module docstrings,
> imports, class/method signatures, and function signatures. Companion to `docs/architecture.md`,
> which covers call flow and the system-wide traceability diagrams.

**Scope.** All first-party Python under `app/`, `scripts/`, `tests/`, and `jyotisha_mcp_server.py` —
**149 files** as of this writing (incrementally updated 2026-09-17 via `scripts/update_file_inventory.py`
to add every file Phases 6-8 had introduced since the prior pass, and to refresh every previously-
documented file's line count and AST-derived signatures -- hand-written directory/file descriptions
were preserved verbatim; only brand-new files got a freshly generated one). **Excluded by design:** `public-git-repos/**`
(OpenJyotish, PyJHora, VedAstro — 338 vendored third-party files used only as reference
implementations for cross-validation, per AGENTS.md §6/Known Conflicts and
`docs/public-repo-review/`; they are not part of this project's runtime and documenting
their internals would misrepresent them as first-party code). Also excluded: generated
`.pyc`/`__pycache__`, and the local `venv`/`.venv` interpreter environments.

Each entry lists a short description followed by its AST-derived structure: classes with
method signatures, then top-level functions with signatures. Signatures are reconstructed
from the AST (defaults/annotations included where present) — not copied by hand.

## Non-Python assets referenced by the rule/narrative pipeline

Rule and narrative behavior in this project lives partly in YAML/Jinja, not just Python (AGENTS.md:
"YAML rule packs in `app/rules/` define interpretation policy... Markdown corpus files are
documentation only, never runtime truth"). These are not `ast`-parseable but are load-bearing, so
they are catalogued here for completeness.

### `app/rules/bphs_top20_rule_cards_v1.yaml`  _2812 lines_

The original hand-authored rule-card corpus (20 richly-cited BPHS rules: chapter/verse, tradition,
examples). Consumed by the **legacy v1 evaluator** (`app/rules/evaluator.py`) via
`load_rule_pack()`. Serves as the permanent provenance/documentation layer even as v2 rules
supersede it operationally (docs/technical-architecture.md §4.3 migration path).

### `app/rules/generic_rules_pilot.yaml`  _116 lines_

Small hand-written pilot pack in the Rule Engine v2 `Rule`/`RuleCondition`/`RuleOutput` shape
(`app/rules/schema.py`) — proof-of-concept fixture used by `test_generic_rule_engine.py` before the
Phase 2-5 generators existed.

### `app/rules/compiled/*_v2.yaml`  (7 generated packs, ~683K total)

Machine-generated Rule Engine v2 packs, each produced by one `app/rules/generators/generate_*.py`
script and regenerated in bulk by `emit_all.py`. Loaded together at runtime by
`load_compiled_rule_packs()`:

| Pack | Generator | Rule count scale |
|---|---|---|
| `planet_in_sign_v2.yaml` | `generate_planet_in_sign.py` | 108 rules (9 planets × 12 signs) |
| `planet_in_house_v2.yaml` | `generate_planet_in_house.py` | 108 rules (9 planets × 12 houses) |
| `lord_placement_v2.yaml` | `generate_lord_placement.py` | 144 rules (12 lagna × 12 house-lord placements) |
| `dosha_v2.yaml` | `generate_dosha_rules.py` | 15 dosha rules (Mangal, Kala Sarpa, Pitra, Guru Chandala, Kemadruma, Papakartari, Ghata, Shrapit) |
| `yoga_v2.yaml` | `generate_yoga_rules.py` | 18 classical yogas |
| `nakshatra_v2.yaml` | `generate_nakshatra_rules.py` | 27 nakshatra profiles + gandanta/Abhukta Mula |
| `dasha_composition_v2.yaml` | `generate_dasha_rules.py` | 81 MD×AD composition rules (9×9) |

These are **regenerated, not hand-edited** — the generator script is the source of truth for each
pack's content; the YAML is a build artifact checked in for runtime loading and diffability.

### `app/engine/narrative/templates/*.jinja`  (3 templates)

`lagna.jinja`, `dosha.jinja`, `yoga.jinja` — rendered by `app/engine/narrative/composer.py`'s
`render_*_section()` functions against a pre-computed, template-ready `display` dict (never raw
chart internals) to produce the Narrative Composer's prose sections.

### `data/charts/*.yaml`  (8 fixtures)

Locked birth-data + computation-settings fixtures, one per person, loaded by `app/fixtures.py`.
`ajay_kumar.yaml` and `sandeep_0700.yaml` are the **golden regression fixtures** used by
`tests/run_suite.py --mode verify` (AGENTS.md §9) and must never be silently edited; the other six
(`itta_madhavi`, `itta_raghunandan`, `itta_sai_nikita`, `itta_sai_shivani`, `roop_kumar`,
`sravani`) are working charts used for readings/compatibility/marriage-timing runs.
