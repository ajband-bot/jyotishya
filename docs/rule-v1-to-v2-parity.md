## 1. A deeper gap than build_plan.md flagged

The plan's diagnosis was "v1 rules run through a hardcoded if-chain, need
migrating to v2 schema." True, but incomplete. Reading `evaluator.py`
directly shows **only the 20 RC-series rules have an `if rid == "RC-0NN"`
branch at all** (and RC-018 is hardcoded to always return `data_gap`
regardless of chart, i.e. 19 rules genuinely computed). **All 28 NK/DG/TR/YL
rules fall through to the final `else` clause** ("No evaluator implemented
yet" / `data_gap`) -- they were never wired, not even naively. On top of
that, every NK/DG/TR/YL rule's own YAML carries
`status: stub_pending_translation` or `stub_high_confidence` with
`citation_status: ocr_signal_only` -- meaning these 28 aren't source-verified
against BPHS/the Telugu corpus yet either. **These are documentation
placeholders, not dormant rules waiting for a Python branch.** Compiling
them to v2 is real fresh rule-authoring work (§3.2 workflow, from scratch),
not a mechanical port.

## 2. Schema gap found while categorizing

`app/rules/schema.py`'s `RuleCategory` enum (`functional_nature`,
`lord_placement`, `dignity`, `aspect`, `yoga`, `dasha`, `transit`, `varga`,
`event`) has **no category for**: nakshatra rules (all 18 NK-series),
arudha/bhavapada rules (RC-014, RC-015), argala rules (RC-013, YL-002), or
karaka rules (RC-011, RC-012). Marked `NEEDS_CATEGORY` below. Before
compiling the Nakshatra rule set (build_plan.md §3.3 item 4), extend the
enum -- don't force-fit into `lord_placement` just to avoid a schema edit.

## 8. Retirement gate (build_plan.md §3.4)

`app/rules/evaluator.py` (v1) may only be deleted once **every** row above
reads `ACTIVE` in a v2 pack with equivalent-or-better coverage. Current
state: **2 of 48 rows have any v2 presence at all** (RC-015 migrated,
RC-001/005/008(partial-via-combustion-subfactor)/010 have narrow pilot
demos, not full parity). This tracker should be updated every time a v2
rule reaches `ACTIVE` status for a row above -- flip the "v2 status" cell,
don't just add a new pilot-pack entry silently.
